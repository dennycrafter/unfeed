# ASSUMPTIONS

One line per decision made where the master document did not decide for us.

1. Expo SDK 57 chosen. Checked October 10, 2026: the Apple App Store lists Expo Go version 57.0.9 (September 2, 2026) and the Expo changelog states that the updated App Store Expo Go supports SDK 57. SDK 58 exists only as a beta. So SDK 57 is the newest SDK the App Store Expo Go can run, and the master document's SDK 54 fallback was not needed.
2. Expo Go on iOS now requires a login to run projects (Expo changelog, September 3, 2026). README and DENIS_TODO tell Denis to use one free Expo account, logged in on the PC with npx expo login and inside Expo Go.
3. The test scripts run green before the real suites exist: `test` uses jest --passWithNoTests and the Playwright scripts use --pass-with-no-tests. T1 and T2 add the real tests and keep the flags.
4. scripts/build-inject.ts is a working stub at T0 so CI can run build:inject. It writes a placeholder generated module. T1 replaces it with the real bundler.
5. The scaffold commit goes straight to local main, matching the master document T0 and gotcha 12, because a PR needs a main to merge into. The PR flow starts with the next ticket once the repo is connected.
6. The Expo template ships demo screens and components under src/app and src/components. They are kept so T0 proves the build; later tickets replace them with the real Unfeed shell.
7. app.json small touches: display name "Unfeed", dark user interface style, and dark splash and Android icon backgrounds (#0b0b0d) to match the dark UI rules in section 10. Real icon and splash art is stretch S11.
8. The task brief pointed at "charter section 5" for the route rules table, but section 5 is environment variables; the Instagram route table lives in section 8.3. The charter wins, so section 8.3 is the source of truth for decide() and the tests.
9. react-native-webview 13 does not re-export its types from the package root, so type only imports come from react-native-webview/lib/WebViewTypes (ShouldStartLoadRequest, WebViewNavigation, WebViewMessageEvent, WebViewProgressEvent).
10. The parity test runs the generated bundle in a node vm sandbox given URL and console, which are the standard globals the script finds in any real page. A bare sandbox has no URL and every parse would fail there for the wrong reason.
11. CI gained a step that runs build:inject then checks git diff on src/inject/generated, so a stale committed bundle fails CI and the app and the later userscripts cannot drift.
12. The injected scripts enforce the route rules inside the page with a neutral tab context, because a page cannot know which native tab is showing. The LinkedIn table has no context dependent rows, so the answer is identical there (the Instagram table's context row is enforced by T2's own entry).
13. Redirects that keep the query string rebuild it with URLSearchParams, so a space inside keywords comes out as +, the standard form encoding.
14. The shared path normalizer collapses duplicate slashes, so a URL like https://www.linkedin.com// counts as home and redirects to Messages exactly like / does.
15. The unread watcher skips an empty document title: at document start the real title is not parsed yet, and an empty title is not a real zero unread state. The first real title posts the count.
16. LinkedIn's global top bar hides through :has() on its feed and network link hrefs, so the whole header goes wherever those links nest inside it.
17. A profile link is only saved as Denis's own when it comes from the /in/me/ redirect started by the Profile tab or the My code "Find my profile" button. Browsing or scanning someone else's profile never overwrites the saved link, so My code keeps showing the right person.
18. A scanned LinkedIn link that contains a vanity path opens on the Profile tab, and every other LinkedIn link opens on the Messages tab. The QR panel covers the page, so a scanned page loaded under the QR tab would be invisible to Denis.
19. The ?scan= and ?profile= router params fill the scan sheet and My code at mount. Deep links and web page loads always start the screen fresh, so the params only need to be read once and no effect is used.
20. T6 userscript headers get one @match per host in the site's rules JSON, so the manager's coverage and the rule coverage cannot drift. That puts instagram.com, www.instagram.com and m.instagram.com in the Instagram script, and linkedin.com and www.linkedin.com in the LinkedIn one. lnkd.in stays out: it is an always allow redirect host, and the script lives on the linkedin.com hop where the next check happens.
21. The userscripts use @noframes (main frames only, both Safari's Userscripts and Tampermonkey support it) so no redirect or hide ever fires from inside an iframe, and @grant none (page context) because the script needs the real DOM and location.replace and uses no manager APIs.
22. The userscripts have no settings UI, so the inject settings fall back to the defaults in src/inject/protocol.ts (allowSharedPosts on, hideCounts off). A browser user who wants different defaults edits that file and rebuilds.
23. The userscript @version is a dedicated USERSCRIPT_VERSION (1.0.0 in src/userscript/header.ts), separate from the inject bundle version tag, so managers like Tampermonkey can detect updates. Bump it whenever a rebuild changes a userscript.
24. Userscript parity is enforced two ways: the committed file body must be byte identical to the generated inject bundle, and the body's decide() must equal native decide() over both full URL tables. Anything that rebuilds the userscripts therefore cannot drift from the app.

25. Instagram's own bars have no nav element on the live site (checked 15 Oct 2026), so the hide is a sweep, not CSS: links whose svg aria-label is a nav label (Home, Reels, Explore, Search, Messages, Notifications, the Instagram logo and so on) are climbed to their first fixed or sticky ancestor that holds no page content. Outside the main area only, a short unpinned block with two or more such links also counts. New post is not a trigger label, so the own profile header with Options stays.
26. The Instagram Post button presses Instagram's own hidden New post control from the page (window.__UNFEED_CREATE__). It does not build a create flow of its own. A page without the control (a DM thread) reports ig-create-missing, the shell moves to the profile tab and tries once more there, then shows a toast. Untested on a phone: if Instagram opens the photo picker straight from that control, iOS may block it because the press does not come from a finger.
27. LinkedIn keeps its own top and bottom bars (Denis, 15 Oct 2026). Every link to /feed/ is hidden except shared posts (/feed/update/) and the composer (shareActive), plus any control whose whole text is Home inside a bar. Notifications and all of My Network are allowed now; /feed/?shareActive opens the composer through the new query match in decide(), and the feed cards behind it are hidden.
28. LinkedIn serves the own profile at /in/me/ and no longer moves to the vanity URL (checked 15 Oct 2026), which is why My code stayed empty. The vanity now comes from the edit links only the own profile carries (li-own-profile message), on any visit to the own profile. The QR empty state also offers Settings, where the link can be typed in; a link typed without https gets it added.
29. Moved to Expo SDK 58 on 23 Oct 2026 because Expo Go on the App Store moved to SDK 58 and stopped opening SDK 57 (Denis saw the version error on his iPhone). The SDK 58 changes that touched this repo: react-native-webview 14 types need an explicit prop generic on the WebView element, Testing Library 14 makes render and fireEvent async, and the static web export now renders the index route in Node, so the web preview unread seed checks for window first.
30. DM video sound (Denis, 23 Oct 2026): the app now sets the audio mode once at launch (expo-audio, included in Expo Go) so web view video plays with sound even when the iPhone's silent switch is on. Every video in the Instagram page also gets playsinline, so iOS keeps it in the page instead of jumping to its own full screen player, which is the most likely cause of the orientation glitch. Not yet checked on the phone.
31. The Stories button (top left on Instagram) still loads the home page, because that is the only place the stories tray lives on the web. The page is now invisible except the tray, which a sweep finds from the story controls themselves ("Story by ...", "Your story", links into /stories/), so the feed cannot paint even when Instagram changes its layout. With no tray after 8 seconds the page says "No stories to show right now." Scrolling is off on that page so more feed never loads.
32. Paste a link: a Link button in the header (both apps) opens a small pop-up. Paste reads the clipboard and opens straight away; typing works too. Instagram links open like a scanned link (no feed around them, shared post rules still apply, so the "Open friends' shared posts" setting must stay on for posts and reels); LinkedIn links open in the LinkedIn page. Other links are refused with a short message.
33. LinkedIn get the app prompts: matched by wording ("Use app", "better on the app", "See more in the LinkedIn app" and similar) and by links into the App Store, Google Play or the app itself. A pop-up is closed with its own Not now or Dismiss button when it has one, otherwise hidden together with its dark backdrop, and page scrolling is given back.
34. Posting. Instagram: iOS only opens the photo picker from a real tap inside the page, and the native Post button is not one, which is why Post did nothing. Post now shows a small in-page sheet; its "Choose photo or video" button presses Instagram's own create control. LinkedIn: a new Post button (header, next to QR) opens LinkedIn's composer at /feed/?shareActive=true. LinkedIn drops shareActive from the address while the composer is open, which the feed rule used to bounce to Messages; the bare /feed/ is now allowed only while the composer is open (rule li-8-composer-session), with the feed cards hidden behind it, and the page goes back to Messages once the composer closes.
35. Single posts and reels always open (Denis, 25 Oct 2026). Rule ig-9-shared-post is now ig-9-single-post and LinkedIn's li-8-shared-post is now li-8-single-post, both plain allow. Your activity was full of them and bounced to Messages. The "Open friends' shared posts" switch did nothing after that, so it is gone from Settings (the stored value is kept, nothing reads it for routing).
36. A reel opened under /reels/<code>/ (Instagram uses that address inside the Reels tab and in some shared links) now goes to its own single reel page /reel/<code>/ instead of to Messages (rule ig-8-single-reel, keeping the code exactly as typed). Bare /reels/ (the Reels tab) and deeper pages like /reels/audio/ still go to Messages. Only links to the Reels tab itself are hidden now, so a reel a friend sends stays visible in the DM.
37. Your activity (/your_activity/...), Instagram's settings pages (/accounts/..., /push/web/settings/, /emails/settings/, /session/login_activity/) and the Accounts Center were already allowed; the route tables now test them so they stay that way.
